# Anki 功能的极简实现

在为个人网站添加 Anki（间隔重复）功能时，我选择了一个极简的方案：**Anki 卡片就是博客文章**。

## 核心想法

与其为 Anki 功能编写大量代码（卡片存储、渲染、API 等），不如直接复用现有的 blogs 逻辑：

- 卡片存放在 `blogs/anki/` 目录下
- 每张卡片就是一个 `.md` 文件
- 可以通过 `#blogs/anki/xxx.md` 直接访问查看
- 卡片同样纳入 RAG 索引，成为数字生命的一部分

## 优点

1. **代码复用** - Markdown 渲染、评论系统、RAG 搜索全部复用
2. **简单** - 不需要额外后端 API，卡片就是文件
3. **统一管理** - 所有内容都是 Markdown，Git 版本控制友好
4. **知识整合** - Anki 卡片也是知识的一部分，纳入 RAG 能更好地构建数字生命

## 需要做的事

1. 前端博客列表过滤掉 `blogs/anki/` 目录（不在首页显示卡片）
2. 新建 Anki 页面，展示卡片列表并实现复习逻辑
3. 记录学习数据（驻留时间等）

## 总结

不要过度设计。一张 Anki 卡片本质上就是一小段知识，和博客文章没有本质区别。复用现有逻辑，用最少的代码实现功能。
